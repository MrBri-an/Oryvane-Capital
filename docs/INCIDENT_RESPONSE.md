# Incident response

1. Triage and classify authentication, authorization, financial, upload, secret, and dependency incidents.
2. Preserve append-only audit and wallet evidence; never edit financial history.
3. Contain affected sessions, credentials, scanner integration, or deployment while retaining evidence.
4. Rotate exposed Supabase/service/scanner credentials and invalidate sessions when required.
5. Reconcile wallet transactions and affected records through audited corrections or reversals.
6. Notify approved legal, operational, and affected-party contacts according to confirmed obligations.
7. Document timeline, scope, root cause, recovery evidence, and preventive actions.

Structured application security logs contain event names, outcomes, masked identifiers, and short reasons only. Passwords, tokens, TOTP codes, complete destinations, and secrets are prohibited.
